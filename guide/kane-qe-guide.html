    The cockpit

    Tab by tab

    Run

    hotkey 1
    • Objective and URL fields; Run (r, visible browser) or Run headless (h).
    • The objective coach holds runs that verify nothing or use unset {{variables}}: Let Claude add checks, Run anyway, Edit.
    • Live steps, extracted values, warnings (low credits, unresolved variables), Test Manager link.
    • When several runs are in progress, a strip lists them all; click one to watch it.
    • After a run: Insights (i), Triage with Claude (t), Playwright code (p), Copy CI command (c), Ask Claude to save as test, Stop (s).
    • First-run guidance: install → login gates, then a checklist (installed, logged in, project, first run, saved test).

    Insights

    hotkey 2 · views 6 7 8
    • Reads the run's evidence pack: per-step model vs browser time, network (HAR) and console per step, kane's verdict and suggested fix.
    • Owner box: PRODUCT BUG, NEEDS A LOOK, CLI / MODEL, PAGE SIGNALS, CLEAN, DID NOT RUN. Third-party ad/tracker errors and errors the page already logged earlier are ignored as noise.
    • Wasted effort: unchanged pages, the same action twice (even worded differently), repeated extractions, step budget used up, long waits.
    • Timeline (6) waterfall: hover or click a step for its timing, requests, console and screenshot (drawn in the terminal). Signals (7) heat grid. Time split (8).
    • Follows the newest run; once you pick a run it stays, with Follow latest.
    • Evidence viewer (v) opens the pack on evidence.lambdatest.com; Validate pack; Rerun; Check flakiness ×3; Fix the test / Draft bug report with Claude.

    Tests

    hotkey 3
    • Saved *_test.md library: ▶ run, status (Test Manager identity), sync (push the bundle).
    • Run on: This machine or Cloud grid (HyperExecute). Target: Web, Android, iOS with a filterable device and OS picker.
    • Run all, Dry run (grid preflight costs nothing), run by tags. Suites show each test's live step.
    • Install grid plugin from here; a refused grid job shows HyperExecute's reason (plan, quota).

    Assurance

    hotkey a
    • Stage strip Ingest → Extract → Review → Design → Run & cover, with counts, designed % and proven % (and when it was last proven).
    • Ingest a file or a Jira, Confluence, Linear or web URL. Questions kane pauses on appear with option buttons (★ recommended) or Let Claude answer.
    • Per use case: Approve, Design tests, gaps with kane's next command. Run N designed tests, Fill variables with Claude, Review with Claude, Evolve stale, View graph, Sync with team.
    • Refreshes by itself when anyone (terminal, CI, teammate) commits to the store or runs a test.

    History

    hotkey 4 · views 6–0
    • Runs (6): every run with owner mark, insights, ↻ rerun, triage; QA report with Claude.
    • Trends (7): duration bars by result, failures by owner, flaky objectives. Credits (8): balance meter, runs left at your average, spend per run.
    • Quality (9): web vitals trend and Measure web vitals; requirement coverage.
    • Sites (0): exploration grouped by site with scenarios, pass counts and pages reached; What to explore next and Triage the failures.
    • Includes runs from terminals and CI on this machine, found on disk.

    Setup

    hotkey 5
    • Version, login, credits (shows an overdrawn balance plainly), project and folder, default URL, window.
    • One-click run settings: mode, assertion mode, bug detection, final validation.
    • Mobile and cloud grid: Check Android / iOS tooling (each failing check with its fix), grid plugin check and install.
    Reading a result

    Owner labels in Insights

    PRODUCT BUGkane says product, and the page logged new first-party errors where it failed.
    NEEDS A LOOKkane and the page disagree; check the screenshot before filing.
    CLI / MODELNothing new went wrong on the page. Headline names a wrong test, the run's settings, or the agent.
    PAGE SIGNALSPassed, but the site logged its own errors (a 5xx, a /undefined/ URL).
    CLEANPassed; only third-party scripts (ads, trackers) logged errors, if any.
    DID NOT RUNRefused to start or out of credits: fix setup or top up.

    Getting it

    Install and first run

    Load the mod

    Point Claude Code at the folder in ~/.claude/settings.json → env.CLAUDE_CODE_PLUGIN_DIRS, or start with claude --plugin-dir ~/Documents/kane-claude-plugin/kane-qe.

    Sign in to KaneAI

    npm install -g @testmuai/kane-cli, then ! kane-cli login --oauth from the prompt. CI uses --username / --access-key; Copy CI command writes it for you.

    Grid and devices

    Grid suites need the remote-execution plugin and a HyperExecute MultiOS plan. Local mobile needs macOS on Apple Silicon with Xcode or Android Studio; Setup's doctor lists what's missing.

    Credits

    A run usually costs 10–50 credits. The pane warns under 15, and a run that runs out reads Out of KaneAI credits, never a test failure.
